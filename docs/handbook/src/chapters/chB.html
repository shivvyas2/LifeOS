Appendix B

BDecision log

Every decision that shaped the app, with the choice made and the reason it was made. Rows from Revision D are kept where they still hold and corrected where they no longer do; the rest were collected from the specs, the commit history and the chapters of this edition.

The log is grouped by area. A row belongs here when a reasonable engineer could have chosen otherwise, so that the next person, usually the author, does not rediscover the reason as a mystery bug. Where a row reverses an earlier one, the earlier one is gone rather than struck through; git has the history.

B.14Study notes

How to use this appendix

  1. Before changing a rule, search this table for the noun; if a row exists, the reason column is the thing to argue with, not the code.
  2. When a row turns out wrong, replace it rather than adding a second; the log records the current decision, git records the old one.
  3. Every spec under docs/superpowers/specs/ has a decisions or alternatives section; a decision that lands in code lands here in the same change.

Which single decision do the most other rows depend on?

One table keyed by day that every source writes into; the arbiter, the digest, the sectors and the widgets all read from it.

Which Revision D rows were reversed rather than kept?

Four tabs, settings behind a gear, on-device first for the coach, and the personal-only audience.

What do the Money, Social and LIFO areas have in common in their reasons?

Each keeps a rule in a place the client cannot reach: a definer function, a server-side prompt, a device-only ledger.
