Appendix C

CGlossary and reading order

The words this book uses in a particular sense, each in one line, and a route through the code for someone studying it one evening at a time.

C.1Glossary

Terms are alphabetical. A term in code is a real symbol in the repository; the rest are the book's names for things the code has no single name for.

TermMeaning
AccountSessionThe app-level object that owns which account scope and ModelContainer are open, and tears surfaces down when the account changes.
AccountStoreThe roster of signed-in accounts in defaults plus one keychain session item per user id.
Agenda cardThe week strip and day rows drawn under a calendar assistant reply, read live from the calendar store rather than parsed from the prose.
ArbiterMetricArbiter.resolve, the pure rank-based rule that decides which source's value a DailyMetrics column keeps when two sources write the same day.
AssistantTurnThe chat router in Insights: cloud first, the device after; refusals and confirmed writes are never retried on the other tier.
AudienceWho a prompt render is for. An onDevice render may carry raw physiology; an offDevice render never does.
AvatarStampmissing, unknown, or at(updated_at): the three answers to whether a person's avatar must be downloaded again.
Band (sector)The floor-to-ceiling range an in-flight sector month can still close in, drawn on the Life board before the month ends.
BlockOne typed line of a note: text, heading, to-do, sketch. A note document is an array of blocks stored as JSON.
Bucket (money)A budget that claims one or more Plaid category codes and counts the month's spend against a limit; the unclaimed band shows what no bucket claims.
Bucket (notes)One of the PARA folders a page can be filed into: Projects, Areas, Research, Archive.
CapacityToday's battery percentage and its source, Whoop recovery or Health HRV, computed once at the start of a live session.
ChatEngineThe protocol both chat tiers implement: a thread and tools in, a reply and partial text out.
Check-inTwo or three questions asked at the monthly close for a sector with no tracked data, scored by CheckInScorer.
Claim keyThe raw category code, or a manual entry's category, that a budget bucket counts. Held by at most one bucket.
Close (monthly)The nine-step walk through the sectors of a month that has ended, one screen per sector, producing a SectorScore row each.
CoastingA projection where the rest of the month continues at the month-to-date pace; the floor of the in-flight band.
Collapse idapns-collapse-id set to lifo-nudge so a phone that was off receives one nudge, not several.
Composition rootRootView: owns every view model, attaches the model context, reloads on ModelContext.didSave and presents every sheet.
ConfirmationBrokerThe actor whose continuation suspends a gated calendar write until the person answers the confirmation card.
ContextBundleThe digest plus money and sector figures, rendered under one character budget for a given audience.
Cursor (Plaid)Plaid's transactions sync bookmark, held on the device per Item and advanced only after a successful ingest.
DailyMetricsThe one SwiftData row per calendar day that every source writes into and every screen reads from. Every field is optional.
Dash ruleA missing value renders as a dash, drawn by the component from a nil String, never as a zero.
DayStatusThe evaluated result of a day against GoalTargets: onTarget, missed or noData. noData never breaks a streak.
DecidedThe share of an in-flight sector's score that can no longer move: one minus the band's width over ten.
Definer functionA security definer RPC in Postgres that runs with its owner's rights and takes the caller only from auth.uid(); used where a row policy cannot express the rule.
Derived rowA NoteTask or NoteLink mirrored out of a page's blocks by the indexer; never synced, always rebuildable.
Design previewThe --design-preview --page= launch harness that renders any screen from an in-memory fixture without an account.
DigestMetricsDigest, the value type of derived daily numbers that is the only health data an engine ever sees.
EffortEstimated exertion from seconds spent in each heart-rate zone, weighted and passed through a saturating curve; a daily credit against capacity.
Effort, Recharge, RestThe app's own 0 to 100 daily comparison scores for group leaderboards; not a vendor's strain, recovery or sleep score.
EndpointerSpeechEndpointer, the pure state machine that decides from microphone level alone when a spoken question is over.
EvidenceThe rows behind a proposed sector score, each normalised to 0 to 1 and weighted; their weighted mean scaled to 0 to 10.
Extras bagDailyMetrics.extrasData, a JSON dictionary of the long-tail Health metrics that have no named column; an absent key means no reading.
Floor and ceilingWhere an in-flight sector closes if the month coasts, and if the remaining days hit the person's targets.
GoalTargetsThe person's targets for steps, sleep, water and weight, read from UserGoals and evaluated per day.
Hand-offThe phone starting a workout on a paired Apple Watch and mirroring it, so the watch owns the HKWorkoutSession and the phone shows it.
hasProfileThe AuthSession flag, from user metadata, that tells a returning person from a new one after the code is verified.
HUDSessionRings, the glass heads-up display of three rings and a rep count over a live session or a workout video; collapses to a bar and can be dragged.
Inbox (notes)Pages whose filedAt is nil: captured but not yet given a home in a PARA bucket.
Ink layerThe page-wide PencilKit annotation canvas on a note, distinct from an inline sketch block.
Item (Plaid)Plaid's name for one connected bank login; billed monthly; one sync cursor each.
LeaseA short server-side lock, thirty seconds for Fitbit, so exactly one caller rotates a single-use refresh token.
LeverOne of seven dimensions (sleep, exercise, steps, water, journal, habits, spend) a projection can perfect on its own to show what still moves a score.
LifeSectorThe enum of nine sectors: Family, Romance, Soul, Friends, Growth, Money, Mission, Body, Mind.
lifo_usageThe per-user, per-day, per-kind token ledger the daily caps read and lifo_debit adds to atomically.
LiveActivityThrottleThe pure decision on whether a new readout deserves an ActivityKit update, so a strap streaming every second stays inside the budget.
LiveSessionReadoutThe one value the HUD, the lock screen and the Dynamic Island all render; every reading optional.
Module hueModuleHue, the one colour a domain screen owns, drawn as a pastel wash on its canvas.
MoneyPartsThe whole and cents of an amount, rounded to total cents first and then split, so a figure never renders as 19.100.
Native checksActivityRecorderChecks and SurfaceNativeChecks: in-process PASS/FAIL runs over real view models that the QA reports paste verbatim.
NoteIndexThe derived task rows, link edges and title index rebuilt from note documents and kept current on every store write.
NudgeThe once-a-day push chosen by a rule and phrased by a model; LIFO speaking first. The fallback sentence covers an outage.
nudge_logOne row per user per local day recording that a nudge went and which trigger fired; never the text.
ObservationA deterministic note on a sector that needs three calendar-adjacent months, such as a repeated answer or a low score.
Origin idThe stable id a note page or migrated plan entry carries so a second device does not produce a second copy.
OTPThe one-time six-digit code sent by email or SMS; the only credential the app has.
PARAProjects, Areas, Resources, Archive: the filing method the notes library sorts by actionability.
PepperOTP_PEPPER, mixed into the hash so otp_events holds no phone numbers.
Pill barPillNavBar, the floating capsule of tab buttons; horizontal on a phone, a vertical rail on an iPad.
Placeholder session idThe Live Activity the watch bridge requests during a background launch, adopted by the timer once the session is real.
Primary wearableThe strap the person named as authority for contested metrics; defaults to Whoop.
Provenance bagDailyMetrics.sourcesData, the parallel dictionary recording which MetricSource wrote each metric, read back by the arbiter.
Provisional rowA chat message shown before the server confirms it, with a negative id, kept in a separate pending array.
Pumping prefixA country code plus the first national digits, used to rate-limit SMS fraud across a number range.
Push stateeasy, onTrack, nearLimit or overLimit: how hard a live session presses against the day's capacity, with its headline and tint.
Quick actionsThe three top-bar actions on every tab: the calendar assistant, LIFO, and begin activity.
railInsetThe 112-point leading room regular-width screens leave for the iPad rail.
ReadoutSee LiveSessionReadout.
Refresh leaseSee Lease.
RepCounterThe pure rep detector on wrist acceleration: two moving averages, an axis lock, signed hysteresis, a timing window and a refractory period.
resolveUserThe Edge Function door: the caller's id from their own JWT, never from the request body.
SAY: lineThe one spoken sentence the model writes first when a reply will be read aloud; SpokenReply splits it from the shown answer.
SCOPEThe server-held guardrail system prompt every lifo-agent request starts with; a client cannot strip what it never carries.
SectorOne of nine areas of life scored monthly on the Life board.
SectorEvidenceFactoryThe one place that turns a month's inputs into evidence rows, used by the close and the in-flight band alike.
Security definer RPCSee Definer function.
SessionKeepAliveThe pure schedule that renews an unexpired session 45 seconds before it lapses.
SleepRecordOne night of sleep as a source record; attributed to the day it ends.
Source rankingmanual 4, authority 3, secondary 2, fallback 1, unattributed 0; the primary wearable is the authority.
SpineThe DailyMetrics table seen as the thing every source writes into and every reader reads from.
SurfaceRouteThe almanac:// deep link (today, health, activity, notifications) the widgets and pushes open, strictly parsed.
SurfaceSnapshotThe credential-free App Group value the widgets and the watch read; a tombstone when ownerID is nil.
TierWhich model a task needs at minimum: the device, or a named cloud task. A floor, not a model.
TogetherThe social hub reached from the profile: People, Groups, Rankings.
TombstoneA row with deletedAt set, kept until the server confirms the delete; also the SurfaceSnapshot written on sign-out.
ToolInvokerThe per-turn executor of tool calls: a six-call cap, the confirmation gate, error shaping, activity chips.
TrendSeriesA fixed window of readings with gaps kept as nil; the average ignores gaps and the latest is the last non-nil.
Two locksThe session and the open store, both required before RootView mounts.
Universal linkhttps://almanac.shivvyas.com/plaid-oauth, claimed by the app through apple-app-site-association so an OAuth bank lands back in the app.
UserGoalsThe stored targets and the dot-grid rule (three of four by default).
UserScopeAn account's id and the path to its own store file and defaults suite.
WatchWireThe versioned, kinded packet and command shapes exchanged between the watch and the phone.
WideningThe library filter relaxing length, then split, when today's plan finds nothing; a tapped chip never widens.
Wiki link[[title]] inside a note block; resolved by folded title at index time into a NoteLink edge, which may dangle.
WorkoutBookmarkA saved and or scheduled mark on a catalog video; deleted when it is neither.
WorkoutRecordOne workout as a source record, with split, reps, sets, video id and an externalID that makes a repeated save one workout.

C.2Reading order

Ten sittings, each an evening. The order builds: the package before the app, the shell before the screens, one feature at a time, the backend where a feature first needs it. Read each file top to bottom, then its test file if one is named, then grep the type across the app to see where it is used. Every chapter's own study notes go deeper into its files; this is the route between them.

Sitting one: the package and the spine

  1. LifeOSKit/Package.swift: the eight targets and which may import which.
  2. LifeOSKit/Sources/Persistence/DailyMetrics.swift: every field optional; the extras and sources bags.
  3. LifeOSKit/Sources/Persistence/MetricsStore.swift: the protocol every screen reads through.
  4. LifeOSKit/Sources/Integrations/MetricSource.swift: the ranks.
  5. LifeOSKit/Sources/Integrations/MetricArbiter.swift: the merge rule, then its tests in IntegrationsTests.
  6. LifeOSKit/Sources/Persistence/LifeOSContainer.swift: the schema list and the migration rule.
  7. LifeOSKit/Sources/Persistence/UserScope.swift: one store per account.

Sitting two: the shell

  1. LIfeOS/App/LIfeOSApp.swift: @main to the first tab.
  2. LIfeOS/App/AppShell.swift: the two locks and the re-root.
  3. LIfeOS/App/AccountSession.swift: switching accounts.
  4. LIfeOS/App/RootView.swift: the composition root; read attachAll and reloadAll first.
  5. LifeOSKit/Sources/Integrations/SupabaseAuth.swift: the three auth calls.
  6. LifeOSKit/Sources/Integrations/SessionRefresh.swift and SessionKeepAlive.swift: when a session is refused and when it is renewed.
  7. LIfeOS/Features/Onboarding/View/SignupScreens.swift: the code field and the returning-user door.

Sitting three: the design system

  1. LifeOSKit/Sources/DesignSystem/Tokens.swift: colours and hues.
  2. LifeOSKit/Sources/DesignSystem/Typography.swift: the one type scale.
  3. LifeOSKit/Sources/DesignSystem/LayoutMetrics.swift: phone against iPad.
  4. LifeOSKit/Sources/DesignSystem/PillNavBar.swift and GradientCanvas.swift: the shell's chrome.
  5. LifeOSKit/Sources/DesignSystem/SoftCard.swift and MetricTile.swift: the card vocabulary and the dash rule.
  6. LifeOSKit/Sources/DesignSystem/MonthGridLayout.swift: calendar maths under test.
  7. scripts/check-typography.sh: the guard.

Sitting four: Today and Health

  1. LIfeOS/Features/Today/ViewModel/TodayViewModel.swift: one snapshot per screen.
  2. LIfeOS/Features/Today/Model/TodaySnapshot.swift and TodayMetric.swift: what a screen is handed.
  3. LifeOSKit/Sources/Persistence/CalendarStore.swift and Integrations/CalendarSync.swift: the windowed cache and the merge.
  4. LIfeOS/Features/Health/View/HealthHubScreen.swift: two halves over one week strip.
  5. LifeOSKit/Sources/Integrations/HealthKitReader.swift and HealthApply.swift: reading everything Health holds and applying it through the arbiter.
  6. LifeOSKit/Sources/Integrations/HealthSyncWindow.swift: which days a sync re-reads.

Sitting five: wearables and the backend door

  7. LifeOSKit/Sources/Integrations/SocialWellness.swift: Effort, Recharge, Rest.
After the tenth sitting Run swift test --package-path LifeOSKit and read the names of the suites as a table of contents of what the app promises. Then open Appendix B and, for any row you cannot explain from memory, go back to the chapter it names.
